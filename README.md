# Canon Timeline Simulator

SillyTavern용 독립 확장. 원작(만화·소설)을 따라가는 롤플에서 원작 대본을 **.md 파일**로 등록해 두고, 체크한 파일 **하나**를 원작 baseline으로 씁니다. 그 파일 안에서도 **현재 Beat 구간(기본 20개)**만 AI에게 보내고, 구간은 사용자가 직접 넘깁니다. 지나간 구간은 원문 대신 **원작의 객관적 사건 기록(Past Canon Events)**으로 줄여서 남깁니다. 다음 파일로 넘기면 방금 지난 파일 구간의 실제 RP 결과를 **원작 에피소드**로 기록하고, 오래된 기록은 에피소드 → 챕터 → 전체로 압축합니다. Persona 카메라 밖에서도 원작은 기본적으로 진행되지만, 실제 RP가 원작을 바꾼 경우 실제 역사가 우선합니다.

「코끼리를 생각하지마」 canon4 패치의 원작 모듈을 떼어낸 것으로, 코끼리 없이 동작하고 코끼리와 같이 켜도 설정·메타데이터·프롬프트 키가 겹치지 않습니다. 장기기억·회상·기록부 같은 기능은 없습니다.

## 설치

SillyTavern의 **확장 › 확장 설치(Install extension)** 에 아래 주소를 넣습니다. 새 버전이 나오면 **확장 관리(Manage extensions)** 의 업데이트 버튼으로 받습니다.

```
https://github.com/KKANGTONG4948/canon-timeline-simulator
```

git 없이 직접 넣으려면 `canon-timeline-simulator` 폴더를 통째로 복사합니다. 두 방법을 같이 쓰지는 마세요(같은 확장이 두 군데에 있게 됩니다).

```
SillyTavern/public/scripts/extensions/third-party/canon-timeline-simulator/
```

새로고침하면 확장 설정 패널에 **📜 Canon Timeline Simulator**가 나타납니다. SillyTavern 1.13.0 이상.

## 사용

1. **파일 추가**로 원작 `.md`를 읽는 순서대로 넣습니다 (예: `01_01-05화.md`, `02_06-10화.md`). 같은 이름을 다시 넣으면 내용이 바뀝니다. ▲▼는 순서만 바꿉니다.
2. 채팅마다 **이 채팅에서 원작 진행 사용**을 켭니다. 켜면 체크(✓)된 파일의 **현재 Beat 구간**이 `<canon_baseline>`으로 들어갑니다. 체크는 "완료"가 아니라 **지금 넣는 파일**입니다.
3. **[다음 파일 ▶]** — 현재 파일의 원작 진행 기록이 아직 없으면, 그 파일의 대본 + 이 파일을 고른 뒤의 채팅 원문 + 기존 원작 기록으로 **원작 에피소드**를 한 번 씁니다(API 1회). 성공해야 체크가 다음 파일로 옮겨가고 구간 시작이 지금 메시지로 바뀝니다. 실패하면 포인터·기록 모두 그대로입니다. 이미 기록이 있는 파일이면 호출 없이 넘어갑니다.
4. **[◀ 이전 파일]** — 기록 없이 체크만 옮깁니다. 파일은 절대 자동으로 넘어가지 않습니다.
5. 원작 진행 기억 — 에피소드가 쌓이면 **원작 챕터 → 원작 진행 전체**로 합쳐집니다(고급 설정의 개수 기준, [원작 기록 정리]로 수동도 가능). 각 기록은 고치기·지우기, 에피소드는 **[다시 요약]**(같은 파일·같은 메시지 구간으로 제자리에서 다시 씀)이 됩니다. 재작성은 이 버튼으로만 일어납니다.

### Beat 구간 (window)

파일 하나에 Beat가 많아도(예: B01~B71) 통째로 넣지 않습니다. `## B01 — 제목` 같은 Beat 제목을 기준으로 Beat를 나누고, **파일에 등장하는 순서대로 20개씩** 잘라 현재 구간만 넣습니다 (B01~B20 / B21~B40 / B41~B60 / B61~B71). 번호로 자르지 않으므로 번호가 건너뛰어도 됩니다.

- 들어가는 것: **파일 header(첫 Beat 앞의 내용) + 지난 원작 사건 기록(둘째 구간부터, 끌 수 있음) + 현재 구간의 Beat**. 그 밖의 Beat 원문은 그 요청에 들어가지 않습니다. `# 2화` 같은 구분 제목은 바로 뒤 Beat에 붙어 다니고, 구간이 화 중간에서 시작하면 그 화 제목을 맨 앞에 붙여 줍니다.
- 파일 목록 아래 **현재 주입 Beat** 영역: 접힌 상태에서는 `현재 주입 Beat: B21 ~ B40`, 펼치면 현재 파일·전체 Beat 수·Window 2 / 4·지난 원작 사건 범위·마지막 Beat 날짜와 함께 **AI에게 실제로 들어가는 블록 그대로**가 보입니다(주입과 같은 계산 결과를 그대로 표시).
- **[← 이전 20 Beat] [다음 20 Beat →]** 로 파일 안에서 구간을 옮깁니다. 다음으로 넘길 때는 방금 지난 구간을 먼저 사건 기록으로 정리하고(아래), 이전으로 갈 때는 호출이 없습니다. 파일을 바꾸는 [◀ 이전 파일] [다음 파일 ▶]과는 별개입니다.
- 어느 구간인지는 **채팅마다** 기억합니다(`chatMetadata…beatWindowIndex`). 체크 파일이 바뀌면 첫 구간부터 다시 시작합니다.
- Beat가 20개보다 적으면 파일 전체가 한 구간, Beat 제목이 하나도 없으면 예전처럼 파일 전체를 넣습니다. (`[CANON_BEAT]` 블록만 있고 제목이 없는 파일은 블록 하나를 Beat 하나로 봅니다.)
- 구간 크기는 고급 설정 「한 번에 넣을 Beat 개수」에서 바꿉니다.
- **마지막 날짜 알림**: 현재 구간의 **마지막 Beat**에 `date: 1990/06/18`(`[TIME]`·`[SCHEDULE]` 어디든, 기간 `1990/07/09~1990/07/11`이면 끝 날짜)이 있고 작중 날짜가 그 날짜에 **이르렀거나 이미 지났으면** 초록색 알림을 **구간당 한 번** 띄웁니다(날짜를 건너뛰어 6/17 → 6/21이 되어도 알림). 한 번 알린 구간은 날짜가 더 지나도 다시 알리지 않습니다. 알림뿐이며 구간·파일을 넘기거나 요약하지 않습니다. 마지막 Beat에 날짜가 없으면 알리지 않습니다. 마지막으로 알린 구간 하나만 기억하므로, 다른 구간에서 알림이 뜬 뒤 예전 구간으로 돌아가면 그 구간은 한 번 더 알립니다.

#### 입력창의 📜 버튼

원작 진행을 켠 채팅에서는 메시지 입력창 옆(보내기 버튼 왼쪽)에 📜 아이콘 **하나**가 생깁니다. 입력창 위에 줄을 더하지 않습니다. 누르면 창이 열리고, 확장 패널을 열지 않고도 구간을 보고 옮길 수 있습니다. 휴대폰처럼 좁은 화면에서는 아이콘끼리 겹치지 않도록, 아이콘이 보이는 동안 글 쓰는 칸이 아이콘 하나만큼 좁아집니다.

```
┌ 📜 지금 주입되는 원작 대본 ───────────┐
│  [← 이전]  [21]~40 / 71  [다음 →]      │
│  [✏️ 이 구간 고치기] [✏️ 머리말 고치기]   │
│  (지금 AI에게 들어가는 블록 그대로)     │
└────────────────────────────────────┘
```

- **창 내용**: 지금 AI에게 실제로 들어가는 원작 대본 블록입니다(패널의 「현재 주입 Beat」와 같은 문자열). 아래에 원작 진행 기록도 접혀 있습니다. 구간을 넘기면 창 내용이 바로 바뀝니다.
- **← 이전 / 다음 →**: 패널의 [← 이전 20 Beat] [다음 20 Beat →]와 **같은 동작**입니다. 「지난 원작 사건 넣기」가 켜져 있으면 다음을 누를 때 똑같이 확인 창이 뜨고 요약을 한 번 호출하며, 실패하면 구간이 넘어가지 않습니다. 꺼져 있거나 이미 기록된 구간이면 바로 넘어갑니다. 첫 구간에서는 이전, 마지막 구간에서는 다음이 꺼집니다.
- **네모 칸(첫 숫자)에 Beat 번호 직접 입력**: 화살표를 누르면 칸의 숫자도 같이 바뀝니다. 칸을 눌러 Beat 번호를 적고 키보드의 이동(Enter)을 누르거나 칸 밖을 누르면, 그 Beat가 들어 있는 구간으로 갑니다. 구간은 처음부터 N개씩 자른 그대로라서 `45`를 적으면 41~60 구간이 열리고 칸은 `41`이 됩니다(어느 구간으로 갔는지 알림이 뜹니다). 번호는 가운데 숫자와 같이 파일 안의 순서입니다(1 = 첫 Beat). 규칙은 화살표와 같습니다. 뒤로 가거나 「지난 원작 사건 넣기」가 꺼져 있으면 바로 가고, 켜져 있는데 건너뛰는 구간의 기록이 없으면 확인 창이 뜬 뒤 그 앞 Beat 전체를 한 번에 정리하고(API 1회) 넘어가며, 정리가 실패하면 넘어가지 않습니다.
- **가운데 숫자**: 지금 넣는 Beat의 위치 / 이 파일의 전체 Beat 수입니다(`21~40 / 71` = 71개 중 21번째~40번째). Beat 번호가 아니라 등장 순서로 세므로 번호가 건너뛰어도 맞습니다. Beat 제목이 없는 파일은 통째로 들어가므로 화살표와 숫자가 나오지 않습니다. 요약 중에는 창의 버튼이 모두 잠깁니다.
- 원작 진행을 끈 채팅, 채팅이 없을 때, 확장을 껐을 때는 버튼이 보이지 않습니다. 고급 설정 › Beat 구간의 **「입력창에 원작 창 버튼 표시」** 로 아예 끌 수 있습니다.
- 파일을 바꾸는 [다음 파일 ▶]은 이 창에 없습니다. 파일 전환은 패널에서만 합니다.

#### 화면에서 원작 대본 고치기

원작 대본이 잘못 적혀 있으면 보던 자리에서 바로 고칩니다. 파일을 다시 만들어 올릴 필요가 없습니다.

- 📜 창의 **[✏️ 이 구간 고치기]** (패널에서는 「현재 주입 Beat」를 펼치면 나오는 **[이 구간 원문 고치기]**): 지금 넣고 있는 구간의 Beat가 **md 파일에 적힌 그대로** 입력 상자에 뜹니다. 고쳐서 [저장]하면 저장된 파일에서 **그 줄들만** 바뀌고 주입에 바로 반영됩니다. 다른 Beat, Beat 사이의 `---`, 파일 끝의 `NEXT_FILE_HINT` 줄은 건드리지 않습니다.
- **[✏️ 머리말 고치기]**: `[FILE HEADER]`로 들어가는, 첫 Beat 앞부분을 같은 방식으로 고칩니다(머리말이 있는 파일에만 나옵니다).
- 상자에 뜨는 것은 주입 블록 전체가 아니라 **파일에서 온 부분만**입니다. 맨 위 지시문은 「지시문」에서, 지난 원작 사건은 [지난 사건 고치기]에서 고칩니다. 구간이 화 중간에서 시작할 때 주입 블록 맨 앞에 붙는 화 제목(`# 1화`)은 파일의 그 자리에 없는 줄이라 상자에는 나오지 않습니다.
- 상자 안에서 Beat 제목(`## B21 — …`)을 더하거나 지우면 파일의 Beat 수가 그만큼 바뀌고, 저장할 때 `Beat 45개 → 46개`처럼 알려 줍니다. 내용을 모두 비우면 저장하지 않습니다.
- **모든 채팅에 적용**됩니다(파일 목록이 전역이라 같은 파일을 쓰는 다른 채팅에도 고친 내용이 들어갑니다). 모델 호출은 없습니다.
- **이미 만든 기록은 바뀌지 않습니다.** 고친 구간으로 만든 지난 원작 사건 기록이 있으면 저장할 때 알려 주니, 사건 내용을 고쳤다면 다음 구간에서 [지난 사건 다시 정리]를 누르세요. 원작 에피소드는 [다시 요약]으로 다시 씁니다.
- 고쳐지는 것은 **확장에 저장된 사본**입니다. 기기에 있는 원본 `.md` 파일은 브라우저가 건드릴 수 없어 그대로이고, 나중에 같은 이름의 원본을 다시 [파일 추가]하면 여기서 고친 내용이 원본으로 덮입니다.
- 요약이 진행 중일 때는 잠깁니다. 상자를 열어 둔 사이 그 구간이 다른 경로로 바뀌었으면 덮어쓰지 않고 다시 열라고 알려 줍니다.

원작 진행 기록(원작 에피소드)은 지금도 **[다음 파일 ▶]** 때만, 그 파일 전체 대본을 기준으로 만들어집니다. Beat 구간을 넘기는 것만으로는 원작 에피소드가 생기지 않습니다.

### 지난 원작 사건 (Past Canon Events)

**[다음 20 Beat →]** 를 누르면 구간을 옮기기 전에, 방금 지난 구간의 **원작 Beat 원문에서 객관적인 사건만** 뽑아 기록에 덧붙입니다(API 1회). 저장에 성공해야 구간이 넘어가고, 실패·거절·취소면 구간도 기록도 그대로입니다.

- 요약 모델에 보내는 것은 **기존 사건 기록 + 방금 지난 구간의 Beat 원문**뿐입니다. 채팅 로그, 원작 진행 기억은 보내지 않습니다. 이 기록은 원작 baseline의 역사이고, 실제 RP에서 달라진 것은 섞지 않습니다(그건 채팅과 원작 에피소드가 맡습니다).
- 적는 것: 누가 무엇을 했는지, 무슨 일이 일어났는지, 무엇이 결정·공개·사실로 바뀌었는지. 적지 않는 것: 감정, 심리 해석, 관계 온도, 동기의 강도, 일시적 반응, "지금 ~한 상태다" 같은 현재 상태 문장.
- **누적**: 모델은 새로 생긴 사건 줄만 내고, 붙이는 것은 코드가 합니다. 그래서 앞 구간의 줄은 구간을 여러 번 넘겨도 글자 그대로 남고(상태 문장으로 바뀌지 않음), 이미 있는 줄은 다시 들어가지 않습니다.
- 주입 모양 (원작 대본 블록 안):

  ```
  [FILE HEADER]
  파일 header

  [PAST CANON EVENTS]
  (재연·회상·설명용이 아니라는 머리말)

  - 코토코가 나오키에게 고백했고 거절당했다.
  - 아이하라 부녀의 집이 무너졌다.

  [CURRENT CANON WINDOW]

  ## B21 — …
  ```

  첫 구간에는 지난 사건이 없으므로 `[PAST CANON EVENTS]`가 빠집니다. Beat 제목이 없는 파일은 예전처럼 파일 전체만 들어갑니다.
- 범위는 **현재 파일 안**입니다. 다른 파일로 넘어가면 그 파일의 첫 구간부터 지난 사건 없이 시작하고, 지난 파일은 원작 에피소드가 맡습니다. 기록은 채팅마다·파일마다 따로 저장되며, 이전 구간으로 돌아가면 그 구간 시점의 기록이 보입니다. 이미 기록된 구간은 다시 넘겨도 호출하지 않습니다.
- 펼친 영역의 버튼: **[지난 사건 고치기]**(직접 수정), **[지난 사건 다시 정리]**(같은 Beat로 다시 씀, API 1회), **[기록 없이 다음 구간]**(정리가 계속 실패할 때만. 빠진 구간은 다음에 넘길 때 함께 정리). 고치거나 다시 정리하면 그 뒤 구간의 기록은 지워지고 넘길 때 다시 만들어집니다.
- 원작 파일을 고쳐서 Beat 순서가 기록과 맞지 않게 되면 그 기록은 쓰지 않고, 다음에 넘길 때 다시 만듭니다.

#### 지난 원작 사건 빼기

고급 설정 › Beat 구간의 **「지난 원작 사건 넣기」** 를 끄면 이 기능 전체가 빠집니다. 기본값은 켜짐이고, 모든 채팅에 똑같이 적용됩니다.

- 끄면 원작 대본 블록에 `[PAST CANON EVENTS]`와 그 머리말이 들어가지 않습니다. `[FILE HEADER]`와 `[CURRENT CANON WINDOW]`만 남습니다.
- 끄면 **[다음 20 Beat →]** 가 확인 창도 요약 호출도 없이 바로 넘어갑니다. [지난 사건 고치기]·[지난 사건 다시 정리]·[기록 없이 다음 구간] 버튼도 보이지 않습니다.
- 이미 만든 기록은 **지우지 않습니다**. 다시 켜면 그대로 돌아옵니다.
- 꺼 둔 동안 넘긴 구간은 기록이 없습니다. 다시 켠 뒤 처음 **[다음 20 Beat →]** 를 누를 때 빠진 구간까지 한 번에 정리합니다(API 1회). 그 전까지는 그 구간의 사건이 블록에 없고, 파일의 마지막 구간에서 켠 경우에는 넘길 다음 구간이 없어 채워지지 않습니다.
- 원작 에피소드·챕터·전체 기록(원작 진행 기억)은 이 스위치와 상관없이 그대로 동작합니다.

### 원작 에피소드가 기록하는 것

1. 실제 채팅이 직접 보여준 주요 원작 사건
2. 채팅에는 없지만 확립된 역사와 충돌하지 않아 **원작 baseline대로 진행된** 중요 사건 (Persona가 그 자리에 없었다·장면이 없다는 것은 미발생 근거가 아닙니다)
3. positive evidence가 있어 실제로 발생하지 않은 중요 사건
4. 유저 개입으로 원작과 달라진 결과
5. 이후 원작 인과에 영향을 주는 변화

권위: **실제 채팅 > 기존 원작 기록 > 원작 대본**. 상위 자료는 하위 자료와 **충돌할 때만** 이기고, 침묵하면 원작 baseline이 그 구간의 기본 역사로 남습니다. 대본에 없는 세부사항을 지어내지 않습니다.

### 전환 알림

파일 끝에 다음처럼 적어 두면, 작중 날짜(`<date>…</date>` 태그, 없으면 날짜가 든 상태창 줄)가 그 시점에 이르렀을 때 **파일당 한 번** 알려줍니다. 완료 판정도, 자동 전환도 아닙니다.

```
---
NEXT_FILE_HINT: 1996-05-12
---
```
또는 `NEXT_FILE_HINT: 1996-05-10 ~ 1996-05-15`. 이 줄과 `---`는 주입 전에 제거됩니다.

## 주입

| 블록 | 키 | 기본 위치 |
|---|---|---|
| 원작 대본 `<canon_baseline file=… beats="B21~B40">` (header + 지난 원작 사건 + 현재 Beat 구간) | `canon_timeline_simulator_md` | 채팅 안 깊이 12 |
| 원작 진행 기록 `<canon_progress>` | `canon_timeline_simulator_memory` | 채팅 안 깊이 8 |

둘 다 고급 설정에서 위치(캐릭터 설정 뒤 / 프롬프트 맨 앞 / 채팅 안)와 깊이를 따로 바꿀 수 있습니다. 디버그 섹션에서 실제 들어가는 텍스트를 볼 수 있습니다.

## 요약 모델

고급 설정의 **요약 모델 프로필**(Connection Manager)을 고르면 `ConnectionManagerRequestService.sendRequest`로, 비우면 지금 채팅의 연결로 `generateRaw`를 씁니다. 응답 최대 토큰·재시도 횟수·기록 언어를 정할 수 있고, 지시문 7개(대본 머리말·지난 사건 머리말·지난 사건 정리·기록 머리말·구간 정리·챕터·전체)는 「지시문」에서 고르고 고칩니다(아래 「지시문 저장·교체」). 지난 사건 정리에는 채팅을 보내지 않으므로, 기록 언어가 「채팅 언어 따라가기」이면 원작 Beat의 언어를 따릅니다. 구간 원문이 상한(기본 24000토큰)을 넘으면 오래된 메시지부터 빼고 기록에 "원문 N개 생략됨"이 남습니다.

### 지시문 저장·교체

「지시문」의 일곱 항목은 각각 **여러 개를 제목을 붙여 저장해 두고 골라 쓸 수** 있습니다. 항목마다 목록이 따로 있습니다.

- 목록의 첫 줄 **기본값 (내장)** 은 확장에 들어 있는 지시문입니다. 읽기 전용이라 여기서는 고칠 수 없습니다.
- **[+ 새 지시문]** — 제목을 묻고, 지금 보이는 내용을 복사해 새 지시문으로 저장한 뒤 그것을 씁니다. 그 아래 칸에서 고치면 바로 저장됩니다.
- 목록에서 다른 것을 고르면 다음 답변·다음 요약부터 그 지시문이 쓰입니다. **[제목 바꾸기]**, **[삭제]** 는 지금 고른 지시문에 적용됩니다. 쓰던 것을 지우면 기본값으로 돌아갑니다.
- **제목은 사람이 고르기 위한 이름입니다.** AI에게는 고른 지시문의 내용만 들어가고, 제목은 주입 프롬프트에도 요약 호출에도 들어가지 않습니다.
- 내용을 모두 비운 지시문을 고르면 기본값이 대신 쓰입니다. 같은 제목을 또 쓰면 `제목 (2)`처럼 번호가 붙습니다.
- 모든 채팅에 공통입니다(확장 설정에 저장). 채팅별로 다르게 고를 수는 없습니다.
- 이전 버전에서 지시문을 직접 고쳐 두었다면 그 내용은 **「기존 지시문」** 이라는 제목으로 저장되어 그대로 쓰입니다.

### 연결 테스트

요약 모델 프로필 선택 바로 아래의 **[연결 테스트]** 는 지금 선택된 프로필로 아주 짧은 요청(`Connection test. Reply with exactly: OK`)을 한 번 보내, 요약 호출이 실제로 되는지 확인합니다.

- 실제 요약(지난 원작 사건·원작 에피소드·챕터·전체)과 **같은 프로필 결정, 같은 요청 경로, 같은 응답 최대 토큰**을 씁니다. 재시도는 하지 않습니다.
- 원작 파일, Beat 구간, 지난 사건 기록, 채팅 로그, 요약 지시문은 보내지 않습니다.
- 텍스트 응답을 받으면 성공(`요약 모델 연결 성공: 프로필 이름`), 요청 오류나 빈 응답이면 실패(`요약 모델 연결 실패: 사유`)를 알림으로 보여줍니다. 사유에서 API 키·토큰·URL 쿼리는 가립니다.
- 프로필이 비어 있거나 목록에 없는 프로필이면 요청을 보내지 않고 바로 알려줍니다. (프로필이 비어 있을 때 요약 자체는 예전처럼 채팅의 현재 연결을 씁니다.)
- 아무것도 저장하지 않습니다. Beat 구간, 지난 사건 기록, 원작 진행 기억, 파일 위치, 날짜 알림 기록, 설정이 그대로입니다. 마지막 결과는 버튼 옆과 디버그 영역에만 잠시 보이고 새로고침하면 사라집니다.
- 테스트 중에는 버튼이 `테스트 중...`으로 잠기고, 끝나면 성공·실패와 관계없이 다시 풀립니다.

## 저장 위치

- 전역: `extensionSettings.canon_timeline_simulator` — 파일 목록(`files`), 위치·깊이·압축·모델 설정, 지난 원작 사건 사용 여부(`pastEnabled`), 입력창 📜 버튼 표시 여부(`inputBar`), 저장한 지시문(`savedPrompts`: 항목별 `{ active, items: [{ id, title, text }] }`, `active`가 비면 내장 기본값)
- 채팅별: `chatMetadata.canon_timeline_simulator` — `on`, `fileIndex`, `fileId`, `beatWindowIndex`, `pastEvents`(파일 id별 `{ count, lastId, text, at }` 목록: 파일 처음부터 Beat `count`개까지의 사건 기록), `startMessage`, `timeline`, `saga`, `archive`, `noticeShownFor`, `lastBeatDateNotice`

채팅 분기 시 ST가 메타데이터를 복사하므로 분기도 같은 진행 상태에서 시작합니다. 다른 채팅에는 아무것도 새지 않습니다.
